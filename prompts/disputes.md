# 异文与解经争议

**默认不处理**，只有 briefing 的 `disputes.enabled` 为 `true` 时才按本文做（用户要求时，工具参数传 `disputes: true`，或工作目录 style.md 设 `disputes: on`）。关闭时不标 `ambiguous`、不列争议读法，也不为争议去查资料。

## 原则

原文有多种合理读法时，不替读者悄悄决定：主译选一种，其他读法作为 alternatives 并列，各自写明依据。各档都一样。争议要**尽量标出**，宁可多标。常见类型：

| kind | 例子 |
|---|---|
| `textual` 经文异文 | 约一 5:7 只见于 TR 的整段；可 16:9-20；旧约 Ketiv/Qere 意义不同 |
| `punctuation` 断句 | 约 1:3-4 `ὃ γέγονεν` 归上节还是下节；罗 9:5 颂赞语归属 |
| `syntax` 句法 | 属格类型（`πίστις Χριστοῦ` 信基督 / 基督的信实）；分词的从属关系；引语止于何处（约 3:16-21、加 2:14-21） |
| `lexical` 词义 | 约 1:5 `κατέλαβεν`（胜过 / 理解）；创 1:2 `רוּחַ`（灵 / 风）；`אֱלֹהִים` 复数形式的理解 |

做法：

- **analyze**：结构上的争议（断句、挂接、引语范围）标 `status: ambiguous`，`alternatives` 写其他切法与 `basis`。
- **translate**：主译写在 `text`，其他读法写进 `alternatives`（每条 `{text, kind, basis}`），主译为何这样取舍写在 `note`。
- **关联读法**：几个子句的可选读法要连起来才成立时（如创 30:32b הָסֵר 读作吩咐拉班挑羊，32c 的工价就得是日后新生的杂色羊），给这几条 alternative 标同一个 `reading`（`R1`、`R2`…，本章内不重复），并在其中一条的 summary 或 basis 里说明这组连起来是什么意思。翻译时同组各句的可选译法也标同一个 `reading`，连读要通。主译各句必须出自同一种理解；某句的可选读法要靠另一句的可选读法才说得通，就归到同一组，不要让读者把不相容的读法拼在一起。
- **依据**（basis）要具体：哪个版本或抄本传统、哪种语法分析、哪类译本或解经传统采此读法。不确定的说法要说明是推测；没有把握的出处不要编造。
- briefing 中的 `disputes`（影响翻译的异文）与 `status: ambiguous` 的子句是系统已知的争议，**必须处理**；其他争议靠你主动识别。

## 底本相关

- 新约：THGNT 标点、SBLGNT/Macula 断句与 NA28/UBS 不同时，主译按 NA28/UBS，另一种断句作为 `punctuation` 类的其他译法列出。
- 主干以外的异文（TR、拜占庭等版本的读法）只作为 `textual` 类的其他译法。
- 取不到 NA28 原文、对断句拿不准时，标为争议。
- NA28 文本里的校勘符号标出了有异文的位置，是争议线索：`⸀`（单词被替换）、`⸁`、`⸂ ⸃`（一段被替换或换序）、`⸄ ⸅`、`⸆`（此处有插入）、`⸋ ⸌`（一段被删）、`⸉ ⸊`、`˸`（标点异文，即断句有争议）、`*`、`[ ]`（存疑的字）。遇到 `˸` 或括住整段的符号，评估是否要列为 `punctuation` / `textual` 争议。
- 旧约 Ketiv/Qere 意义不同时，列出 Ketiv 的译法。

## 子句分析（analyze）

- 两种切法都说得通时，选一种提交，`status` 设为 `ambiguous`，另一种写进 `alternatives`（`summary` 说明读法，`basis` 写依据）。断句传统有分歧（如约 1:3-4）、修饰语挂接有两解、引语止于何处不确定，都属此类。翻译时这些子句必须给出对应的其他译法。
- **提交前逐节自查歧义**。第一个读得通的切法不一定是唯一的，每节都过一遍下面几问，找到第二种说得通的读法就标 `ambiguous`。`ambiguous` 不表示两种读法一样好：主读法证据更强，另一种只要语法上成立、意思说得通，也要列出，由人工译者取舍。
  1. **挪动边界**：把每个子句交界处的成分（夹在两个主句之间的从句，如 `כִּי`、`אִם`、`אֲשֶׁר`、不定式、分词、`ὅτι`、`ἵνα`、`ὡς` 引导的从句；交界处的介词短语、副词、时间词、呼格）试着挪到另一边，看前后两句是否仍然合语法、意思是否说得通。从句改挂后句时，它常成为后句的条件、时间或原因。
  2. **重音不是否决权**：旧约的马所拉重音（`athnach`、`zaqef` 等）代表中世纪的一种断句传统，主切分依它；但第 1 问挪出来的读法即使跨过 `athnach`，只要成立照样列出，`basis` 注明与重音不合。例：赛 40:3 `קוֹל קוֹרֵא בַּמִּדְבָּר פַּנּוּ דֶּרֶךְ`，重音把 `בַּמִּדְבָּר` 归下句（“在旷野预备道路”），七十士译本与太 3:3 归上句（“在旷野有声音呼喊”）。
  3. **Macula 种子的挂接与你不同**（如种子把某个从句放在顶层，你把它挂在前句下），说明另一种挂法有人主张，按第 1 问检验。只看挂接（父子关系）；子句怎么切仍按切分规则，不必因此把种子的包裹层单列。
  4. 同一个词形能不能有两种分析，进而改变主语或子句关系？如希伯来文前缀 `ת` 的未完成式第二人称阳性与第三人称阴性同形，Hiphil 不定式独立式与祈使式同形，分词与完成式同形；希腊文中关身与被动同形、直说与虚拟同形。
  5. 七十士译本等古译本在这里的断句或语法理解明显不同时，那就是另一种读法的线索。
- `ambiguityHints`（旧约）是系统按词形标注与马所拉重音找出的歧义线索（同形异析、`athnach` 前可改挂下半节的从句等），**逐条检验**：成立的标 `ambiguous` 并写进 `alternatives`，不成立的不必说明。线索不全，上面的自查照做。
- `textualVariants` 列出影响翻译的经文异文；异文改变句子结构时（多出或少一个子句），在相关子句的 `note` 记下。
- 新约：NA28 本身标了标点异文（`˸`）或断句传统有分歧时，标 `status: ambiguous`，另一种断句写进 `alternatives`；THGNT/SBLGNT/Macula 的不同断句也放进 `alternatives`。
- 逻辑关系（`logic`）有两种都说得通时，主读法写在 `logic`，另一种写进 `alternatives` 的 summary。

## 翻译（translate）

系统已知的争议：

- `clauses[].status` 为 `ambiguous`：子句分析的其他读法在该子句的 `alternatives` 里 → **必须**给 alternatives，并在 note 写主译理由。
- `readings`：子句分析的关联读法组（如 `R1` 涉及 32b、32c、33b）→ 组内每句都要给 `reading` 相同的 alternative，按这组读法连起来译，连读要通；只给一句会被拒。译文里自己发现的关联读法也可以新起一组（编号不与已有的重复）。分批翻译时关联读法组不要拆到两批里。
- `clauses[].disputes.textual`：影响翻译的经文异文 → 给 `kind: "textual"` 的 alternative（异文读法的译文），或在 note 说明为何不影响译文。

`ambiguityHints`（旧约）是系统按词形与重音找出的歧义线索。子句分析没有处理到的，逐条检验，成立的列 alternatives。

此外**主动**标出其他争议（断句、句法、词义）。提交前自查：

- 隐含的主语、宾语，以及你补出的指代词（如“[这些]”），所指是否还有第二个候选？
- 译文与前后文（尤其后面几节的叙事）有没有说不通的地方？经文自身的张力往往说明还有另一种读法，应列为 alternative，不要在 note 里替原文调和掉。
- note 里写到“也可理解为……”“另一读法……”的，就要列为 alternative，不要以“意思相近”“不影响译文”为由省掉；是否采用由人工决定。例：

```json
{
  "clauseId": "43001005b",
  "span": 1,
  "text": "黑暗却没有胜过光",
  "note": "κατέλαβεν 取“胜过、抓住”义，与上下文光暗对立相合",
  "alternatives": [
    {"text": "黑暗却不理解光", "kind": "lexical", "basis": "καταλαμβάνω 也有“领会、明白”义（徒 4:13 的 καταλαβόμενοι）；拉丁通俗译本 comprehenderunt 采此解"}
  ],
  "renderings": [ ... ]
}
```

- 关系从句带原因、让步、条件、目的意味，读法会实质改变意思时，列 `kind: "syntax"` 的 alternative。
- 希伯来文无标记关系从句：子句分析没有把它挂在名词下（`modifies`）、而你判断是关系从句时，按 `syntax` 争议处理。

alternatives 的译文用同一档位来写；不需要为 alternatives 提供 renderings。
