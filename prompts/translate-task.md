# 翻译（translate）

基于子句分析，按工作目录设定的档位（briefing 的 `approach`，见 [literalness.md](literalness.md)）产出中文译文，并给出实词的译法对照，通过 `submit_translation` 提交。下面的示例和“span”“叙事文”两节按默认的第 2 档（直译）写；其他档位与之不同的地方，以 literalness.md 为准。

## 流程

1. 调 `build_translation_briefing(range)` 一次。还没有子句分析的节会报错，先做 analyze。范围较大时按自然段分批。
2. 读 `approach`（档位）、`clauseView`（缩进结构）、`clauses`、`tokens`、`terms`（每个实词义项的术语表条目与既有译法）、`precedingTranslations`（前文）。
3. 逐子句翻译，组成 `translations` 数组提交。
4. 若返回 `errors` 或 `consistency`，按提示修正后**整节**重提；已写入的节不要重提。
5. 本段新确定的专名、术语，用 `upsert_glossary` 写入术语表。

## 每个子句一项

```json
{
  "clauseId": "1001001a",
  "span": 1,
  "text": "起初神创造了诸天与大地",
  "renderings": [
    {"tokens": "o010010010012", "zh": "起初"},
    {"tokens": "o010010010021", "zh": "创造"},
    {"tokens": "o010010010031", "zh": "神"},
    {"tokens": "o010010010052", "zh": "诸天"},
    {"tokens": "o010010010072", "zh": "大地"}
  ],
  "paraTitle": "神创造天地"
}
```

- `text`：译文。第 1–3 档中补出的词用 `[ ]` 标出（范围按档位，见 literalness.md），第 4、5 档不用 `[ ]`；NA28/UBS 双括号内的经文，各档译文首尾都加 `〚 〛`。
- `supplied`：可选，补词的说明，每条 `{text, note}`，`text` 是某个 `[ ]` 里的文字（同一补词出现多次时加 `at`）。补出名词主语等需要交代的补词写在这里。
- `renderings`：`clauses[].contentTokens` 中的**每个实词**都要有一条；`zh` 必须是**去掉 `[ ]` 后的** `text` 里实际出现的字串。
  - 几个词整体译为一个中文词或短语时，`tokens` 写区间 `首-末`。第 4、5 档重组句子时常这样用。
  - `zh` 出现不止一处时，可以加 `at`（`zh` 在去掉 `[ ]` 后的译文中的起始位置，从 0 数）指明是哪一处；不给时系统按词序自动定位。briefing 里已有译文的 renderings 带着 `at`，改了译文后不必手算，删掉或留着都行。
  - 实词有意不译时 `zh` 写 `∅`；第 1–3 档还要加 `note`。
  - 虚词可以不给 rendering。
- `alternatives`：争议处的其他译法，每条 `{text, kind, basis}`（见下文“争议”）。
- `note`：主译的取舍理由；有 alternatives 时必填。
- `paraTitle`：可选，本子句开始新段落时给出段落标题（纯文本）。
- 用了扩展工具时加 `"sources": ["ai", "ext:commentary"]`。

## 争议

`clauses[].disputes` 是系统已知的争议：

- `analysis`：子句分析标为 ambiguous 的其他读法 → **必须**给 alternatives，并在 note 写主译理由。
- `textual`：影响翻译的经文异文 → 给 `kind: "textual"` 的 alternative（异文读法的译文），或在 note 说明为何不影响译文。

此外**主动**标出其他争议（断句、句法、词义），类型与写法见 principles.md 的“争议处理”。例：

```json
{
  "clauseId": "43001005b",
  "span": 1,
  "text": "黑暗却没有胜过光",
  "note": "κατέλαβεν 取“胜过、抓住”义，与上下文光暗对立相合",
  "alternatives": [
    {"text": "黑暗却不理解光", "kind": "lexical", "basis": "καταλαμβάνω 也有“领会、明白”义（徒 4:13 的 καταλαβόμενοι）；拉丁通俗译本 comprehenderunt 采此解"}
  ],
  "renderings": [ ... ]
}
```

alternatives 的译文用同一档位来写；不需要为 alternatives 提供 renderings。

## 用词统一

`terms` 列出范围内每个实词义项（`senseKey`）：

- `glossary`：术语表条目。`locked` 必须照用；`preferred` 是默认译法。
- `history`：本书卷已有的译法及次数、出处。
- `maculaZh`、`ubsZh`：参考简义，不是定译。

规则：

1. 有 `locked` → 必须用该译法，否则该节被拒（各档都一样）。
2. 有 `preferred` 或 `history` → 默认沿用；确需不同时，在该 rendering 的 `note` 写理由，否则该节被拒并在 `consistency` 中列出。第 4、5 档不拒，只在 `consistency` 里提示。
3. 都没有 → 这是首次出现，认真选词：有 `preference`（术语偏好）时默认用它，不用 `avoid` 里的译法；重要的词提交后用 `upsert_glossary` 固化。
4. 同一 senseKey 下的正当分化（比喻义与本义、语域差异），写 note 后系统会放行；若这种分化会反复出现，考虑在术语表里按 `senseKey` 分别建条目。

## span（子句合并）

基准是逐句翻译（`span: 1`）。第 1 档不合并（系统拒绝 span>1）；第 3 档起判据 B 不再限制；第 4、5 档按意思合并，诗歌平行句也可以合并，但要写 note。以下是第 2 档的规则。

**判据 A（合并前置）：后置状语造成语序倒置。** 原文把条件、时间、情状成分放在主句之后，中文按习惯要前置——拆开就会留下悬空的尾句。范围由 briefing 里 `approach.clauseOrder` 决定（来自 style.md 的 `clauseOrder`；第 1 档固定为 `source`，第 4、5 档固定为 `fluent`）：

- `fluent`（默认）：中文前置才通顺的，一律合并前置。
- `source`：时间从句、“直到”从句、不定式时间从句保留原文语序，各自成句；中文后置也能读通时不合并。

两种选项下，条件从句（`אִם`、`ἐάν` 等）以及拆开会留下悬空尾句的情况都要合并前置。典型形态：

- `אִם`、`כַּאֲשֶׁר`、`בְּטֶרֶם` 引导的后置从句
- `בְּ` / `כְּ` + 不定式的时间从句后置
- `waw` + 独立人称代词 + 分词的情状小句
- 新约中后置的 `ἐάν`、`ὅταν`、`ὡς` 时间/条件从句，同理判断

**判据 B（默认不合并）：中文也可后置的从句。** 原因（`כִּי`、`ὅτι` 表原因、`γάρ`）、关系（`אֲשֶׁר`、关系代词）、目的（`לְמַעַן`、`ἵνα`）从句各自 `span: 1`。引语框架（“神说：”）与引语内容也各自成句。

**判据 C（不得合并）：同型平行对句。** 诗歌体的平行句一律各自成句，即使合并更顺口。

合并写法：

- 合并 N 个连续子句时，首句 `span: N`，其后 N-1 句 `span: 0`、`text: ""`、不给 renderings（renderings 都写在首句上）。
- 合并后的 `text` 用 `\n` 分行，行数与覆盖的子句数一致，**行序按中文语序**。
- 合并不跨节。

## 连词

连词（וְ、καί、δέ、γάρ、οὖν 等）不要死板对译：

- 按它在上下文中的逻辑功能翻译（顺接、转折、因果、结果、解释），或者不译。
- 叙事中串联动作的 וְ / וַ、καί，中文通常不必译出；需要时用“就”“便”“于是”等自然衔接。
- 表示对比、转折、原因、推论时，要把这层逻辑关系译出来（如“却”“因为”“所以”）。
- 连词不要求 rendering，也不纳入用词统一检查。

## 关系从句

拆句、前置、用代词或重述先行词承接等常规手法照常用；以下是容易出错、或与档位相关的几点：

- **希伯来文复指成分**：`אֲשֶׁר` 从句里回指先行词的代词后缀或副词（`בּוֹ`、`עָלֶיהָ`、`שָׁם` 等）。从句译成前置“所……的”定语时不再译出复指成分（“我所住的地”，不是“我所住在其中的地”），该词 rendering 写 `∅`，第 1–3 档 note 写“复指成分，前置定语中不译”；第 1 档可以保留字面。从句后置、单独成句时，复指成分正好译成承接的代词（“我曾住在那里”）。
- **承接的指代要唯一**：后置从句用“他、它、这”承接时，先行词必须是前面最近的同类名词；中间隔着别的名词就重述先行词。第 1–3 档重述的先行词是补词，放进 `[ ]`。
- **隐含的逻辑关系**：关系从句有时带原因、让步、条件、目的意味（如带将来时直陈或 `ἄν` + 虚拟语气的关系从句）。第 1–3 档保留关系从句的形式，这层意思写进 note；读法会实质改变意思时，列 `kind: "syntax"` 的 alternative。第 4、5 档可以直接用“因为”“虽然”“为要”等连词译出。`ὅστις` 在通用希腊文里常与 `ὅς` 无别，不要一见就译成“既然”“因为”。
- **希伯来文无标记关系从句**：诗歌与部分散文省略 `אֲשֶׁר`，小句直接贴在（多为无冠词的）名词后面，如伯 3:3 `יוֹם אִוָּלֶד בּוֹ`（我出生的那日；`בּוֹ` 是复指成分）。不要译成并列句。子句分析没有把它挂在名词下（`modifies`）、而你判断是关系从句时，按 `syntax` 争议处理。
- **前置定语的长度**：中文名词前的“的”字结构超过两层，或前置后头重脚轻，就改为后置成句，或用“那……的，他……”的外位结构。

## 标点

- 引号要成对：直接引语用 “”，引语中再引用用 ‘’。
- 同一段引语跨节时，只在开始的那节加 “，在结束的那节加 ”；中间各节开头不再加 “。

## 个人风格

briefing 有 `style` 时，按 principles.md 的“个人风格与术语偏好”处理：原文两种译法都成立时采用其中的偏好。

## 叙事文

以下是第 1–3 档的要求；第 4、5 档按 literalness.md 处理重复和强调，但原文明示的主语仍要译出。

- 保留重复结构，不为中文文风删减重复。
- 非主语前置成分有强调或焦点功能，译文要体现。
- 原文明示的主语（尤其重复出现的专名主语）必须译出，不得省为零主语。
